# LocalSSH v0.2.0 Security Hardening Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Remove libssh2 from LocalSSH, use macOS OpenSSH for file transfer, keep secrets in native Keychain APIs, constrain renderer file authority, enable CSP, and gate releases on dependency security checks.

**Architecture:** Terminal and file transfer will share OpenSSH connection options and ControlMaster sockets so SFTP can reuse an active terminal transport when credentials match. SFTP operations are driven through `/usr/bin/sftp` attached to a PTY so password prompts can be answered from Keychain/in-memory credentials without placing secrets in argv, environment variables, or temporary files. Local upload/download access is mediated by opaque backend grants generated only by native file selection or native drag/drop events.

**Tech Stack:** Tauri 2, Rust 2021, portable-pty, macOS `/usr/bin/ssh` and `/usr/bin/sftp`, `security-framework` 3.x, React 19, TypeScript 5, GitHub Actions.

**Spec:** Conversation-approved v0.2.0 security scope on 2026-08-23.

## Global Constraints

- Remove `ssh2` and `libssh2-sys` from the dependency graph.
- Never place SSH/SFTP passwords in process arguments, environment variables, SQLite, logs, or temporary files.
- Preserve saved server profiles and existing Keychain account names so v0.1.x users do not lose saved passwords.
- Preserve Terminal, SFTP tabs, uploads, downloads, Finder drag/drop, separate SFTP credentials, and SSH/SFTP connection reuse where usernames match.
- The renderer may upload/download only files or directories explicitly approved by native OS selection/drop events.
- Release builds fail on high/critical npm advisories or RustSec advisories.
